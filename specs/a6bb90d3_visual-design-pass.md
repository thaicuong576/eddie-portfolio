## Root causes of known problems
1. **3+1 Work grid**: auto-fit with 4 items at 1240px. Fix with a count-aware grid (below).
2. **Double line under header**: header `border-b` + first section (`Approach`) `border-t` directly after the hero. Fix: sections drop `border-t` on the first one (or use a shared `Section` wrapper that draws one top rule except when `first`), header keeps single hairline. Verify visually at the hero->Approach boundary and on case pages.
3. **375px header wraps to 3 rows**: nav is flex-wrap with 7 items + pill. Fix: header is a single row at all widths, fixed height (e.g. 56px mobile / 72px desktop, expose as CSS var `--header-h` in globals.css and use it for `scroll-mt`, hero margin, etc.). On <640px nav becomes a horizontally scrollable single row (`overflow-x-auto`, no-scrollbar, `whitespace-nowrap`, scroll-snap) with a right-edge fade mask using ground colour, OR shortened to fit; the page itself must not scroll horizontally. Wordmark smaller (~22–24px) on phones. Contact pill stays last/always visible (put it outside the scrolling area, `shrink-0`). All touch targets >= 40px tall where feasible. Verify nav labels from `content/sections.ts` (read lengths first).
4. **Hero blur unreadable on phones**: reduce/limit blur (max ~3–4px desktop, 0–2px on narrow, or drop blur and use opacity/rotation/scale only), start opacity higher (>=0.55), reduce scatter distance on narrow screens so letters stay in-frame and word reads early (letters fully legible by ~p=0.4). Letters finish converging before dock begins.
5. **Case pages plain column**: redesign as a two-column layout on lg (sticky meta sidebar: tag, status, tools, links; main: Context / Approach / Outcome as numbered or ruled blocks with larger lead), single column on mobile with meta first. Add a hero band for the title with `proves` as lead, a bottom "next/back to work" link using `ui.backToWork`. Optionally prev/next project links computed from `projects` array with labels added to `ui.ts` (e.g. `nextCase`, `previousCase`) — only if cheap.

## Design direction (builder decides details; keep calm and exact)
- Concept: a "ledger / model" aesthetic — hairline rules, tabular mono numerals, restrained teal accent, generous but not empty space. Cards read like statement/summary tiles; experience/achievements read like ledger rows with a mono date column.
- Fonts: may swap via `next/font/google` in `app/layout.tsx` **font config only** (do not touch the `metadata` export). Suggestion: keep Geist Mono (or IBM Plex Mono / JetBrains Mono) for numerals/labels, and pair a distinctive but sober sans or serif display (e.g. Instrument Serif / Fraunces for headings, Geist/Inter for body). Keep `--font-sans` / `--font-mono` variable names (add `--font-display` if used, register in `@theme inline`). Use `font-variant-numeric: tabular-nums` on numeric/mono labels. Letters of the hero must keep Fin = ink, Tech = system.
- Type scale: fluid via `clamp()` for h1/h2; body >= 16px on mobile; mono labels >= 12px. Contrast: `muted` (#57584F) on ground/surface passes AA; do not use `rule` colour for text; teal on ground passes AA; do not drop text opacity so far that contrast <4.5:1.
- Shared primitives (new files fine, server components): `components/ui/SectionShell.tsx` (id, eyebrow, heading, intro, spacing, scroll-margin from `--header-h`, single top rule except first), `Eyebrow`, maybe `Tag/Pill`. Refactor the six sections to use them to remove the repeated markup.
- Focus: global `:focus-visible { outline: 2px solid var(--color-system); outline-offset: 3px; border-radius }` in globals.css; on teal-filled elements use an ink/ground ring so it stays visible. Hover: subtle translate/underline/border-colour transitions, CSS only, wrapped so `prefers-reduced-motion` disables transitions/transforms.
- Heading order: one `h1` per page (hero name on home; project title on case page), `h2` per section, `h3` for cards/rows. Remove any skipped levels. Links must say where they go: card links should have accessible names including the project title (e.g. wrap card in a link containing the h3 + "Read the case →", or add visually-hidden title via existing text); achievements "View →" links should get `aria-label`/sr-only text combining `ui.viewLabel` with the item title (build string in component from content, not new copy) and `rel="noopener noreferrer"`.
- Hero: keep seven-letter scatter→converge→dock. May retune timing (e.g. converge by p≈0.5, dock 0.6–0.95), scale, easing, scroll track (shorter on mobile, e.g. 220–260vh), background (replace/refine the 80px grid; keep subtle), hints, readout. Hand-off must be exact: docked letters' final font-size/position/letter-spacing/line-height must match the header wordmark (compare via `getBoundingClientRect` of the wordmark; scale = wordmarkFontSize/fs, read the wordmark's computed font-size rather than hard-coded 30). Switch visibility at dock>=1 with no one-frame gap/flash. Header height must be read from DOM (`--header-h` / offsetHeight) not 88 literal. Keep `useIsomorphicLayoutEffect`, rAF-throttled scroll, resize + `document.fonts.ready` re-measure (new font changes widths). Re-measure on narrow widths so `ww` never exceeds `W - 2*padding` (fs = min(0.19W, 0.36H) with 7 letters may overflow—verify at 375px; letters scattered must not cause horizontal scroll: hero sticky box has `overflow-hidden`, keep it, and ensure `overflow-x: clip` on body/html as a safety net).
- Reduced motion: end state, header wordmark + nav visible, no 300vh track (`h-auto`), no flying word, no transitions. Keep existing `motion-reduce:` approach and also test the `mql` change path.
- Intro block: make it a composed layout (eyebrow, name h1, paragraph) positioned so it doesn't collide with the docked header on short phones (check 375x667 and 320x568). Consider hero CTA links only if labels exist in content (`navSections`/`contactSection`), else skip.
- Header: shared look between `ScrollHero` header and `SiteHeader`. Preferably extract a single presentational `HeaderBar` (children for wordmark/nav) or keep them in sync via shared class constants in one file so they cannot drift. Case page header uses `<Link href="/">`; home uses in-page anchors. Add `aria-current` not required. Sticky with ground at ~90% + `backdrop-blur` is fine (no extra hue).
- Work cards: count-aware grid implemented with **static** Tailwind class strings (Tailwind can't see dynamic ones). Use a 6-col grid at `lg`: n%3==0 -> each `lg:col-span-2`; n==4 or even -> `sm:col-span-3` (2x2); n==5 -> first two `lg:col-span-3`, rest `lg:col-span-2`; fallback `col-span-3` and last odd item `col-span-6`. At `sm` (>=640) 2 columns (odd last spans full), `<640` 1 column. Equal-height cards (`h-full flex flex-col`). Build a small `spanClasses(n, i)` helper in Work.tsx. Verify with a temporary 5 and 6 project check (do NOT commit changes to `content/projects.ts`; revert after).
- Toolkit, Experience, Achievements, Approach, Contact: restyle with the shared shell. Experience/Achievements rows: grid `md:grid-cols-[200px_1fr]`, mono tabular date column, hover row highlight (surface background) where row has a link. Placeholders like `[Year]`, `[Status]` must render literally—never filter/format them; check mono styling doesn't uppercase-transform bracketed text in a way that changes it (CSS uppercase is OK visually but prefer none for placeholders; keep strings as-is in DOM).
- Contact: strong closing section; email/links come from `content/profile.ts` as today; make links large tap targets.
- Footer: only if a footer string exists in content; otherwise none.
